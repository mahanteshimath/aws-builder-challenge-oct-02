# Proof: coding agent connected to AWS

**Coding agent:** Snowflake Cortex Code (VS Code extension), running in the builder's workspace with shell access.
**Connection:** AWS CLI v2 (`aws-cli/2.36.34`) + AWS SAM CLI + boto3, using the named profile `hackathon` (IAM user `hackermonty`, region `us-east-1`). No access keys are stored in the repository; the agent invokes the CLI, which reads the local profile.
**Agent tag:** every AWS call made by the agent's deploy workflow sets `AWS_SDK_UA_APP_ID=cortex-code-agent` (see `scripts/deploy.ps1`), so CloudTrail records `app/cortex-code-agent` in the event `userAgent`. This makes the agent's actions independently verifiable in the account's CloudTrail event history.

## 4. What the agent did with this connection (in order)

1. Inspected local AWS profiles and confirmed access (`sts get-caller-identity`), listed Bedrock foundation models and `us.amazon.nova-*` inference profiles.
2. Created the Amplify app and `main` branch; wrote `template.yaml` and deployed the SAM stack (API Gateway, two Lambdas, private S3 bucket, IAM roles, logs).
3. Uploaded the GeoJSON layers to S3, built the SPA with the API URL and deployed it to Amplify; applied CSP and security headers.
4. Ran `scripts/smoke_api.py` (15/15) and a Playwright browser run of the full demo (`scripts/e2e_flow.py`, 14/14, zero console errors) against the public URLs.
5. Rebuilt the dataset from real OpenStreetMap + SRTM data for Kurla, Mumbai, redeployed the stack, S3 data and frontend, and re-ran both verification suites against the live deployment.
